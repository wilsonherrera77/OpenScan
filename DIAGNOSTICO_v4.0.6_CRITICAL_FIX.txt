ERROR #1: Mensaje Engañoso (view_document.dart:956-958)
───────────────────────────────────────────────────────────────────────

Ubicación: lib/screens/view_document.dart

Código ANTES (v4.0.5):
```dart
// Enqueue logic in try/catch (lines 924-951)
try {
  await uploadService.enqueueGenericDocument(...);
} catch (e) {
  print('❌ Failed to enqueue: $e');
  // Error silencioso - solo print
}

// Mensaje SIEMPRE mostraba éxito (lines 956-958)
String displayText;
(savedDirectory != null)
    ? displayText = "PDF Saved at\n$savedDirectory\n\n✅ Enqueued for Tejido sync"
    : displayText = "Failed to generate pdf. Try Again.";
```

Problema:
  El mensaje "✅ Enqueued for Tejido sync" se mostraba SIEMPRE si el
  PDF se guardó, INCLUSO si el encolamiento falló dentro del try/catch.

  El usuario veía "éxito" pero el PDF nunca se encolaba.

Código AHORA (v4.0.6):
```dart
// Track success status
bool enqueuedSuccessfully = false;
String? enqueueError;

try {
  await uploadService.enqueueGenericDocument(...);
  enqueuedSuccessfully = true;
} catch (e) {
  enqueueError = e.toString();
}

// Show HONEST message
if (savedDirectory != null) {
  if (enqueuedSuccessfully) {
    displayText = "PDF Saved at\n$savedDirectory\n\n✅ Enqueued for Tejido sync";
  } else {
    displayText = "PDF Saved at\n$savedDirectory\n\n⚠️ Not enqueued: ${enqueueError}\n\nSync manually or check logs";
  }
}
```

Impacto:
  ✅ Usuario ahora ve el ERROR EXACTO si falla el encolamiento
  ✅ No más mensajes engañosos
  ✅ Posibilidad de diagnosticar problemas en dispositivo


ERROR #2: "Share PDF" NO Encolaba (view_document.dart:874-898)
───────────────────────────────────────────────────────────────────────

Ubicación: lib/screens/view_document.dart

La app tiene DOS opciones para crear PDF:

1. "Share PDF" (icono PDF) - línea 876
   → Guarda PDF en directorio de app
   → Comparte via Android Share
   → ❌ NO encolaba para Tejido (v4.0.5)

2. "Save to device" (icono celular) - línea 901
   → Guarda PDF en /Documents/Lumara/PDF/
   → ✅ SÍ encolaba para Tejido

Código ANTES (v4.0.5):
```dart
ListTile(
  leading: Icon(Icons.picture_as_pdf),
  title: Text('Share PDF'),
  onTap: () async {
    // Guarda PDF
    await fileOperations.saveToAppDirectory(...);

    // Comparte
    await Share.shareXFiles([XFile(pdfPath)], text: 'Compartir PDF');

    Navigator.pop(context);
    // ❌ NO encola a Tejido
  },
),
```

Problema:
  Si el usuario usaba "Share PDF" (opción más intuitiva), el PDF
  NUNCA se encolaba para Tejido. Solo funcionaba con "Save to device".

Código AHORA (v4.0.6):
```dart
ListTile(
  leading: Icon(Icons.picture_as_pdf),
  title: Text('Share PDF'),
  onTap: () async {
    // Guarda PDF
    await fileOperations.saveToAppDirectory(...);

    // ✅ NUEVO: Auto-encolar a Tejido
    try {
      final uploadService = Provider.of<UploadService>(context, listen: false);
      final pdfFile = File(pdfPath);

      if (await pdfFile.exists()) {
        await uploadService.enqueueGenericDocument(
          documentFile: pdfFile,
          title: fileName,
        );
        print('✅ Shared PDF enqueued for Tejido sync');
      }
    } catch (e) {
      print('❌ Failed to enqueue: $e');
    }

    // Comparte
    await Share.shareXFiles([XFile(pdfPath)], text: 'Compartir PDF');

    Navigator.pop(context);
  },
),
```

Impacto:
  ✅ Ambas opciones (Share PDF y Save to device) ahora encolan
  ✅ Usuario puede usar cualquier flujo y sincronizará
  ✅ Más intuitivo - menos confusión
