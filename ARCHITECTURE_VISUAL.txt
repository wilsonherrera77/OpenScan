║                        DATA FLOW: UPLOAD (Key Feature)                     ║
╚════════════════════════════════════════════════════════════════════════════╝

    PersonSelectionScreen
            │
            ↓
    DocumentMetadataScreen (Select type + number)
            │
            ↓
    DocumentMetadata stored in CensusProvider
            │
            ├─→ UploadScreen
            │    │
            │    ├─→ DocumentRepository.checkDocumentExists()
            │    │    │
            │    │    └─→ Backend: POST /api/documents/check/
            │    │        ├─ Exists + HIGH quality → "Skip"
            │    │        ├─ Exists + LOW quality → "Replace?"
            │    │        └─ Not exists → "Proceed"
            │    │
            │    ├─→ [Camera Capture]
            │    │    └─→ DocumentPreviewScreen
            │    │        ├─ ImageQualityChecker (brightness, contrast, sharpness)
            │    │        │
            │    │        ├─ HybridOcrService
            │    │        │  ├─ LocalOcrService (Google ML Kit) [70% confidence]
            │    │        │  └─ OpenAI Vision (fallback if needed)
            │    │        │
            │    │        ├─ [Approve or Re-take]
            │    │        └─ (Optional: Crop/Rotate)
            │    │
            │    └─→ [Upload Flow]
            │        ├─ ImageOptimizer (Phase 2: compress 60-80%)
            │        ├─ DocumentRepository.uploadDocumentForPerson()
            │        │   └─ PaperlessApiClient.uploadDocument()
            │        │       └─ HTTP POST /api/documents/
            │        │
            │        ├─ Online → Direct upload
            │        ├─ Offline → Queue to SQLite
            │        │
            │        └─ UploadService
            │            ├─ Retry logic (max 3 attempts)
            │            ├─ Exponential backoff
            │            └─ Sync status stream
            │
            └─→ BackgroundSyncService
                 ├─ Foreground task (Android SDK 36+)
                 ├─ Periodic sync every 15 minutes
                 └─ NetworkMonitor (connectivity check)

╚════════════════════════════════════════════════════════════════════════════╝

    User (JWT Auth)
    ├─ AuthToken

        │

        │

            ├─ required_documents: int
            ├─ digitized_documents: int
            └─ DocumentReview (Phase 2: approval/rejection)

╔════════════════════════════════════════════════════════════════════════════╗
║                    OFFLINE SUPPORT ARCHITECTURE                            ║
╚════════════════════════════════════════════════════════════════════════════╝

    Device goes OFFLINE
            │
            ↓
    UploadService detects offline
            │
            ├─→ Queue upload to SQLite
            ├─→ Store: file_path, person_id, metadata
            └─→ Status: PENDING
                │
                └─→ Show: "Saved offline, will sync when connected"
                          │
                          └─→ Device goes ONLINE
                              │
                              ↓
                          BackgroundSyncService triggers
                              │
                              ├─→ Foreground task started
                              ├─→ Retry all pending uploads
                              ├─→ Exponential backoff (if failure)
                              ├─→ Max 3 attempts
                              │
                              ├─→ Success → Mark as UPLOADED, delete queue
                              └─→ Failure → Keep in queue, retry next sync

    Periodic Sync: Every 15 minutes (even if online)
    ├─ Check for pending uploads
    ├─ Re-sync failed uploads
    └─ Update statistics
